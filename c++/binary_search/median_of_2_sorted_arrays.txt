class Solution {
public:
    double median(vector<int> &arr1, vector<int> &arr2) {
        // find smaller array
        // A < B
        // bsearch on choosing 0 to all of A and rest from B
        // left = right then at the border we have our elements
        // total/2

        int m = arr1.size();
        int n = arr2.size();
        if(m>n) return median(arr2, arr1);
        
        int total = m+n;

        int half = (total + 1)/2;

        // empty [] is also possible
        int low = 0, high=m; // [1,2,3] -> [],[1],[1,2],[1,2,3]
        while(low <= high) {
            int mid1 = low + (high-low)/2;
            int mid2 = half - mid1;

            int l1 = (mid1 > 0)? arr1[mid1-1] : INT_MIN;
            int r1 = (mid1 < m)? arr1[mid1] : INT_MAX;
            int l2 = (mid2 > 0)? arr2[mid2-1]: INT_MIN;
            int r2 = (mid2 < n)? arr2[mid2] : INT_MAX;

            if(l2 <= r1 && l1 <= r2){
                // odd
                if(total % 2 == 1){
                    // take elements from the correct arrays
                    return max(l1,l2);
                }
                // even
                else{
                    return (max(l1,l2)+min(r1,r2)) / 2.0;
                }
            }
            // need less from 1 and more from 2
            else if(l1 > r2){
                high = mid1 - 1;
            }
            // need less from 2 and more from 1
            else{
                low = mid1 + 1;
            }
        }  
        return 0;              
    }
};

This code snippet and the logic for calculating the median are typical of the **binary search approach** to finding the median of two sorted arrays, `nums1` (size $m$) and `nums2` (size $n$), with $m \le n$.

Here is an explanation of the purpose of the variables and the median logic:

## 📐 Binary Search Approach Variables

### `int total = m + n;`
* **Purpose:** Calculates the **total number of elements** in the merged array.

### `int half = (total + 1) / 2;`
* **Purpose:** Determines the **size of the left half** of the conceptual merged array.
* The median of a set of numbers is based on splitting the data into two halves. The binary search approach aims to find a **partition** point in `nums1` (and consequently in `nums2`) such that all elements in the "left half" of the combined set are less than or equal to all elements in the "right half."
* **Why `(total + 1) / 2`?**
    * If `total` is **odd** (e.g., 9), `(9 + 1) / 2 = 5`. The left half has 5 elements, and the right half has 4 elements. The median is the largest element in the left half (the 5th element).
    * If `total` is **even** (e.g., 10), `(10 + 1) / 2 = 5`. The left half has 5 elements, and the right half has 5 elements. The median is the average of the largest element in the left half (5th element) and the smallest element in the right half (6th element).
    * This formula conveniently gives the required number of elements in the left partition for both odd and even total lengths.

---

## 🔢 Median Calculation Logic

The binary search aims to find the optimal cut (or partition) in `nums1` (`cut1`) and `nums2` (`cut2`) such that:
1.  **Partition Size:** $cut1 + cut2 = half$
2.  **Order Property:** $\max(L1, L2) \le \min(R1, R2)$
    * $L1$: Element *just* to the left of the cut in `nums1`.
    * $L2$: Element *just* to the left of the cut in `nums2`.
    * $R1$: Element *just* to the right of the cut in `nums1`.
    * $R2$: Element *just* to the right of the cut in `nums2`.

Once the optimal cuts are found, the median calculation depends on the total length:

### **Why when odd: `max(l1, l2)`**

* **Scenario:** `total` is **odd** (e.g., 9 elements).
* The left half has one more element than the right half (`half = 5`).
* The **median is the single middle element**, which is the **largest element in the left half**.
* The left half consists of elements up to $L1$ and $L2$. Therefore, the largest element in the entire left half is $\mathbf{\max(L1, L2)}$.

### **Why when even: `(max(l1, l2) + min(r1, r2)) / 2.0;`**

* **Scenario:** `total` is **even** (e.g., 10 elements).
* The left half and right half have the same number of elements (`half = 5`).
* The **median is the average of the two middle elements**: the largest element in the left half and the smallest element in the right half.
* **Largest in Left Half:** This is $\mathbf{\max(L1, L2)}$.
* **Smallest in Right Half:** This is the smallest element from $R1$ and $R2$, which is $\mathbf{\min(R1, R2)}$.
* The median is thus $\frac{\max(L1, L2) + \min(R1, R2)}{2}$. The division by `2.0` ensures a floating-point result.

> *Note: For array boundaries (where $cut1=0$, $cut1=m$, $cut2=0$, or $cut2=n$), $L1, L2, R1,$ or $R2$ are often treated as $\mathbf{-\infty}$ or $\mathbf{+\infty}$ to handle edge cases correctly within the $\max$ and $\min$ operations.*
